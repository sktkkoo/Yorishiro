# 自律モードの実機受入確認

このチェックリストは `continuous-companion.md` の達成条件を実機で確認するためのもの。チェック項目を作ったこと、fixture試験の成功、アプリの生存だけを達成の証拠にしない。現時点の実測結果を記入した文書ではない。

## 1. 開始前に固定する情報

- 実行するnativeアプリのビルド／commit、workerの版、workspace、personaを記録する。
- 選択したbackend、provider、model、認証**方式と参照先**、許可したファイル操作とcommandIdを記録する。資格情報本文は記録しない。
- 既存の未回収依頼があれば、元のrequestId・backend・保存世代で状態を確認する。観測のために再送・リセット・経路変更しない。
- 接続診断は静的な設定確認にすぎない。実モデルでの完了と区別する。
- 起動中のアプリが編集後のコードを読み込んでいることを確認する。ソース側の試験成功を実機への反映証拠にしない。

認証、課金、権限の変更や破壊的な障害注入は、その操作に対する許可がある場合だけ行う。この文書自体は許可を追加しない。

## 2. 実モデルの短い確認

任されたworkspace内で有用な小作業を一つ選び、調査・成果ファイル作成・許可済み固定コマンドによる検証・結果提示までを実モデルで確認する。

記録するもの：requestId、backend、作成／完了時刻、成果ファイルと差分、検証結果、ツール証拠が完全かどうか。認証情報や私的な会話の全文を観測ログに複写しない。

受領は完了ではない。証拠が不完全な失敗依頼について、空のツール一覧を根拠に「実行されていない」と判断しない。

## 3. 12時間・24回の通常運転

新しい出力ファイルを使って観測する。実アプリのPIDと接続先に置き換える。出力先は実行ディレクトリからの相対パスで指定できる。

```sh
python3 -B scripts/observe-continuity-soak.py \
  --pid <native-app-pid> \
  --output new-soak.jsonl \
  --duration-seconds 43260 \
  --live-mcp-url http://127.0.0.1:18743/mcp
```

- 自律Onのまま、画面を閉じたりターミナル表示へ切り替えたりしても進行することを確認する。
- 人が送った作業で回数を水増ししない。`return`／`followup`の完了依頼を24件以上確認する。
- 同じ試験区間で12時間以上かつ24件以上を満たす。別ログの都合のよい区間を足し合わせない。
- 実際の成果と依頼を照合する。完了24件だけで有用な成果24件があるとは扱わない。
- 停止・失敗・観測欠落を隠さず残す。観測間の無停止はサンプルだけでは証明できない。

既存ログの再集計は読み取り専用で行う。

```sh
python3 -B scripts/observe-continuity-soak.py --summarize new-soak.jsonl
```

`sampledWindowSeconds`、`uniqueCompletedAutonomousRequests`、backend別件数、実ツール進展、最長観測間隔、エラー、live未確認とdisk/live差異を確認する。集計の `goalAchieved: false` は意図的で、ログの回数から品質や無停止を自動認定しない。

## 4. 再起動復帰は別の試験区間

通常運転の無停止確認と、意図的にアプリを止める復帰試験を混同しない。許可された専用試験で次を確認する。

1. 受理済み依頼のrequestId・backend・保存世代と、既に発生したファイル／コマンドの効果を控える。
2. アプリ停止と再起動を行い、人から新しい作業指示を送らずに同じ依頼の回収と後続自律処理が続くか確認する。
3. 元の依頼が別ID・別backendで再実行されていないこと、成果やコマンド効果が重複していないことを照合する。
4. 回収が不明なら不明のまま残す。再送で見かけの成功に置き換えない。

Pi workerのプロセス終了、nativeアプリの終了、電源断は別の障害。worker単体の試験成功でアプリ全体や電源断の復帰を認定しない。

## 5. 成果品質の確認

試験区間で生み出された成果を、出典のrequestId、何を改善したか、検証、未解決点と一緒にユーザーへ提示する。ユーザー本人の100点満点の評価を記録し、95点以上かを確認する。エージェントの自己採点、返信がないこと、テスト成功率で代用しない。

## 最終判定に必要な証拠

| 条件 | 必要な証拠 |
| --- | --- |
| 12時間以上 | 同じ通常運転区間の実測時刻と観測欠落の確認 |
| 24回以上 | その区間の重複排除済み自律完了requestIdとbackend |
| 無停止 | エラー／中断／待機の実態と、観測だけでは不明な区間の照合 |
| アプリ再起動後の継続 | 別試験の同一依頼回収・後続起動・副作用非重複の証拠 |
| 95点以上 | 成果一覧に対するユーザー本人の明示的な採点 |

一つでも不足すれば未達または未確認と記録する。再試験で成功しても、以前の失敗記録を消さない。
