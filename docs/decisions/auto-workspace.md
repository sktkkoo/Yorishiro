# 会話と成果を中心にした Auto workspace

Status: experimental implementation（2026-10-31）

ユーザーが決めるのは、任せたい結果、その対象、結果をどう扱うか。相談から依頼が形になり、同じ場所で作業結果を受け取る。設定項目の説明を読んでから仕事を始める構成をやめ、典型的な使い方を host がまとめて扱う。

## 画面と会話

タイトルバーの Auto は `AutoWorkspace` を開く。右側の作業領域を使い、幅280pxの既存 `CharacterSurface` と3D runtimeを維持する。暗幕や新しいモデルは追加しない。既存のターミナルと Main Agent は保持し、Auto表示中だけターミナルを操作対象から外す。設定 Pack の自動作業ウィジェット、旧 `AutonomyPanel`、個別の頻度・上限・操作・日次相談・自動許可の設定UIは撤去する。

コミュニケーションは「話しながら」と「静かに」で切り替える。

- **話しながら**: 「話しかける」から本体の音声会話を開始する。接続後はミュートと会話終了を使う。入力の文字起こしを送信するUIや読み上げチェックは置かない。
- **静かに**: マイクと音声出力を止めて文字で相談する。GPT Liveを止めた後にVoice Summaryだけ復帰しないよう、hostの音声所有権で静かな状態を保持する。保存済みの音量設定は変更しない。

Codexを Main Agent にしている場合、音声も文字も現在の Main thread に接続する。対応していない agent での文字相談は既存の `autonomy_consult` を使い、同じ共有ドラフトへ結果を渡す。使えない経路や稼働中workerとの競合はエラーを示し、応答を捏造しない。Codexへの切り替えが必要な音声開始は既存の確認・セットアップ経路へ進む。

モードを変えても入力中の文章と仕事は残る。会話を終了すること、Autoを閉じること、仕事を止めることは独立した操作である。Autoを閉じても状態購読とnativeの進行通知を維持する。表示する会話状態と発話は実際のイベントに由来するものに限り、音声開始の受領だけで「発話した」と扱わない。

## 相談から明示的な委任へ

最初は現在の作業フォルダを引き継ぐ。保存済み・提案済みのフォルダは上書きしない。会話と手入力が共有する依頼案には目的とフォルダを示し、必要ならその場で直せる。会話の開始、追加指示、`autonomy_propose` の受領だけでは作業を開始しない。

「任せる」または「依頼を切り替える」の近くで、フォルダ内の編集・移動・退避と、送信・公開には別の確認があることを示す。明示操作後、新しい契約を次の内部プリセットへ正規化する。

| 項目 | 新しい委任 |
|---|---|
| 実行経路 | `workMode: auto`。対象と許可からhostが選ぶ |
| ローカル操作 | `write` / `move` / `trash` |
| 作業前の判断 | `reviewMode: automatic` |
| 外部操作の自動許可 | `automaticActionApproval: false` |
| 旧PR専用フラグ | `publishPullRequest: false` |
| 内部の起動予算 | `intervalMinutes: 30` / `maxRunsPerDay: 4` |

これらは表示モードの設定ではなく、委任時の実行条件である。モードを変えるだけでは権限を増減しない。保存済み契約の狭い操作範囲・日次相談・自動許可・予算は明示的な依頼切り替えまで維持する。既存の外部自動許可がある場合は現在の仕事に表示する。

委任の直前に入力を同期する。表示後に目的やフォルダが変わった場合は委任を中止して最新案を確認させる。native側でも `reviewedDraftId` と目的・対象・実行条件の一致を検査する。新しい音声提案を古い表示の承認で有効にしたり、別の下書きを消したりしない。

## 実行と結果

現在の実行単位は一つの目的と一つのフォルダであり、複数の独立タスクを同時に走らせるUIは提供しない。委任した目的の達成まで必要な仕事を判断し、目的が完了したら待つ。結果の準備だけで必要な送信などが残る場合は、具体的な確認と実行結果を分けて扱う。保存済みの旧daily契約では日々の仕事の判断を維持する。

進行中は短い状態と停止操作を示す。停止要求後の処理終了待ちは `stopping` とし、停止完了と同一視しない。依頼の変更は共有ドラフトまでに留め、稼働中の契約を会話の返答だけで置き換えない。再開は保存済みの範囲を再利用する。

成果はnativeのsummary・変更パス・検証結果・成果物の保存先から表示する。取得していない本文や差分を生成してプレビューにしない。履歴、利用可能な成果物を開く操作、復元を同じ領域に置き、失敗や復元の競合は実際の状態を残す。

送信・公開などの確認カードでは対象、影響、具体的内容を示し、その要求IDとdigestへ承認を結び付ける。会話中の相づちは承認にならない。既存の `pendingWork` と `pendingActions` は引き続き判断できる。実行経路、復元、プロセスの停止、許可の境界は [autonomous-document-work.md](autonomous-document-work.md) に従う。

## 検証と限界

コンポーネントテストでは、画面を閉じた際の購読保持、文字下書きの保持、明示委任、旧権限の維持、下書きの競合、会話終了と仕事停止の分離、日次判断、具体的承認、成果と復元エラーを確認する。音声接続・文字相談・権限の競合は、それぞれnative clientとbackendのテストでも扱う。

GPT Liveへの実マイク入力から委任・作業完了までの通し確認を、このUI変更の検証済み事項としては扱わない。音声の品質と実機での会話確認は別途必要である。アプリ終了中の実行、正確な時刻の予約、複数目的の並行実行もこの変更には含まない。
