# 会話と成果を中心にした Auto workspace

Status: experimental implementation（2026-10-31）

相談から依頼が形になり、同じ場所で作業結果を受け取る。ユーザーが決める目的と対象、いまの状況、次に動く見通しを先に示す。設定項目の説明を読んでから仕事を始める構成をやめ、典型的な使い方を host がまとめて扱う。頻度など結果の見通しに関わる条件は隠さず、その場で変更できる。

## 画面と会話

タイトルバーの Auto は `AutoWorkspace` を開く。右側の作業領域を使い、幅280pxの既存 `CharacterSurface` と3D runtimeを維持する。暗幕や新しいモデルは追加しない。既存のターミナルと Main Agent は保持し、Auto表示中だけターミナルを操作対象から外す。設定 Pack の自動作業ウィジェット、旧 `AutonomyPanel`、操作・日次相談・自動許可を並べた旧設定UIは撤去する。

文字入力は音声の接続状態によらず使える。話しながらURLやファイル名を送る場合も、会話を終えて文章で相談する場合も同じ入力欄を使う。「話しながら／静かに」のモード選択や、その選択の保存は行わない。

入力欄のフォーカスは中立色で示し、緑の枠を重ねない。送信は矢印だけにし、読み上げ用の名前と送信中の状態を残す。委任ボタンの重複する矢印や成果全体を囲む装飾を減らし、依頼・判断・結果のまとまりは余白と見出しで示す。

音声操作は実際の接続状態から決まる。未接続なら「話しかける」、接続中ならミュートと会話終了を示し、接続待ちも区別する。音声は本体のGPT Liveによる会話であり、文字起こしを送信するUIや読み上げチェックは置かない。Autoを開くだけではマイクを開始せず、すでに接続している会話は維持する。

Autoを開いている間はhostの音声所有権でVoice Summaryなどの代替読み上げを抑制する。音声会話がなければ静かなままで、会話を終了しても代替読み上げは復帰しない。保存済みの音量設定は変更しない。Autoを閉じるとこの抑制だけを解除し、進行中の音声会話や仕事は停止しない。

Codexを Main Agent にしている場合、音声も文字も現在の Main thread に接続する。音声接続中に送った文字は、その会話へのユーザーの補足として渡す。送信の受領と返答の完了は区別し、受領だけで架空の返答を表示しない。対応していない agent での文字相談は既存の `autonomy_consult` を使い、同じ共有ドラフトへ結果を渡す。使えない経路や稼働中workerとの競合はエラーを示し、入力を失わない。Codexへの切り替えが必要な音声開始は既存の確認・セットアップ経路へ進む。

音声を開始・終了しても入力中の文章と仕事は残る。会話を終了すること、Autoを閉じること、仕事を止めることは独立した操作である。Autoを閉じても状態購読とnativeの進行通知を維持する。表示する会話状態と発話は実際のイベントに由来するものに限り、音声開始の受領だけで「発話した」と扱わない。

## 相談から明示的な委任へ

最初は現在の作業フォルダを引き継ぐ。保存済み・提案済みのフォルダは上書きしない。会話と手入力が共有する依頼案には目的とフォルダを示し、必要ならその場で直せる。会話の開始、追加指示、`autonomy_propose` の受領だけでは作業を開始しない。

「任せる」または「依頼を切り替える」の近くで、フォルダ内の編集・移動・退避と、送信・公開には別の確認があることを示す。明示操作後、新しい契約を次の内部プリセットへ正規化する。

| 項目 | 新しい委任 |
|---|---|
| 実行経路 | `workMode: auto`。対象と許可からhostが選ぶ |
| ローカル操作 | `write` / `move` / `trash` |
| 作業前の判断 | `reviewMode: automatic` |
| 外部操作の自動許可 | `automaticActionApproval: false` |
| 旧PR専用フラグ | `publishPullRequest: false` |
| 実行間隔・上限 | 表示した依頼案の値を維持。新規案の初期値は30分・直近24時間で4回まで |

これらは委任時の実行条件である。音声の接続・切断や文字の送信だけでは権限を増減しない。保存済み契約の狭い操作範囲・日次相談・自動許可は明示的な依頼切り替えまで維持する。既存の外部自動許可がある場合は現在の仕事に表示する。頻度だけを変更しても、これらの権限や進め方は変わらない。

委任の直前に入力を同期する。表示後に目的・フォルダ・頻度が変わった場合は委任を中止して最新案を確認させる。native側でも `reviewedDraftId` と目的・対象・実行条件の一致を検査する。新しい音声提案を古い表示の承認で有効にしたり、別の下書きを消したりしない。

## 実行と結果

現在の実行単位は一つの目的と一つのフォルダであり、複数の独立タスクを同時に走らせるUIは提供しない。委任した目的の達成まで必要な仕事を判断し、目的が完了したら待つ。結果の準備だけで必要な送信などが残る場合は、具体的な確認と実行結果を分けて扱う。保存済みの旧daily契約では日々の仕事の判断を維持する。

進行中は短い状態と停止操作を示す。停止要求後の処理終了待ちは `stopping` とし、停止完了と同一視しない。依頼の変更は共有ドラフトまでに留め、稼働中の契約を会話の返答だけで置き換えない。再開は保存済みの範囲を再利用する。

現在の依頼と依頼案には実行間隔と直近24時間の上限を一行で示し、開くとその二項目を変更できる。委任時に選んだ値を初期値へ戻さない。稼働中の頻度変更は専用のnative更新で保存し、表示時の契約との一致を検査する。目的・対象・権限・有効状態を変えず、進行中のworkerや確認待ちを取り消さない。

待機中には上限も考慮した次回の実行見込みを示す。作業中・確認待ち・停止・中断はそれぞれの状態を優先し、実行できない日時を予約として表示しない。旧daily契約の翌日の相談も区別する。実行間隔は通常の作業開始時刻が基準で、承認後の継続経路には終了後から待つ場合もある。アプリ起動中の確認で実行するため、表示は正確な時刻の保証ではない。

成果はnativeのsummary・変更パス・検証結果・成果物の保存先から表示する。取得していない本文や差分を生成してプレビューにしない。作業理由・ブランチ・成果物の保存先は「作業の記録」にまとめ、理由が空でも保存済みの情報を確認できるようにする。記録を開くだけではファイルや外部URLを開かない。履歴、利用可能な成果物を開く操作、復元を同じ領域に置き、失敗や復元の競合は実際の状態を残す。

送信・公開などの確認カードでは対象、影響、具体的内容を示し、その要求IDとdigestへ承認を結び付ける。会話中の相づちは承認にならない。既存の `pendingWork` と `pendingActions` は引き続き判断できる。実行経路、復元、プロセスの停止、許可の境界は [autonomous-document-work.md](autonomous-document-work.md) に従う。

## 検証と限界

コンポーネントテストでは、画面を閉じた際の購読保持、音声接続中も使える文字入力、文字下書きの保持、明示委任、旧権限の維持、下書きの競合、会話終了と仕事停止の分離、日次判断、具体的承認、成果と復元エラーを確認する。頻度の表示・編集・委任時の維持と、確認待ちなどの状態に応じた次回表示も対象とする。音声接続中の文字送信、代替読み上げの抑制、権限の競合、実行を中断しない頻度更新は、それぞれnative client・音声所有権・backendのテストでも扱う。

GPT Liveへの実マイク入力から委任・作業完了までの通し確認を、このUI変更の検証済み事項としては扱わない。音声の品質と実機での会話確認は別途必要である。アプリ終了中の実行、正確な時刻の予約、複数目的の並行実行もこの変更には含まない。
