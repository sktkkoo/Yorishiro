# Live への過去の会話の自動注入を止める

2026-11-15。利用者から、接続時に昔の話を流し込まず、必要になった時だけ参照する方針への同意を得た。

引用 JSON の断片を適用した接続でも、架空の対話と文字化けが再発した。0.169.0 の v3 は
`appendText` の role を保持せず `session.context.append` に変換し、500 UTF-8 bytes ごとに送る。
各断片に説明を付けても、受動的な記憶の更新やグループ全体の原子的な適用は保証できない。
特定の文字列が生成された内部原因を確定したわけではない。

## 方針

- アプリは接続時に continuity の内容を読み込んで Live に送らない。起動時には人格指示と固定の会話・依頼方針だけを native developer initial items に渡す。Codex の起動時履歴も明示的に無効のままにする。
- 会話中の continuity 変更イベントを Live に再投入する購読と輸送 API を撤去する。UUID、記憶本文、過去の話者列を受動的な音声入力として送らない。
- 過去の話が必要な場合は、固定指示に従い backing agent が現在の persona の `continuity_context` を必要に応じて読み、訂正・忘却を確認した上で関連する答えを返す。過去の記録が今の音声文脈にないことを、忘却や喪失として扱わない。
- 未完了作業の再開、「前の続き」「あれ」のような過去への参照、以前の好み・決定が回答に関わる場面では、明示的な「覚えている？」を待たずに関連する記憶を参照する。既知の情報を利用者に再説明してもらう前に調べる。一方、相づちや単独で完結する質問ごとの照会、接続時の全件先読みは行わない。
- 実際の user transcript の保存、正規の記憶・参照元 ID、忘却、メモリー UI、通常のテキスト／自律実行の文脈、依頼済み作業の進行・結果通知は維持する。既に進行中の音声セッションの会話も削除しない。
- 実際のユーザー発言を作らず、一人の assistant として話す。接続時と無回答時には架空の依頼や返答で空白を埋めない。依頼済み作業の新しい確認済み結果は報告できる。

## 検証と限界

合成の記憶・識別子を含む古い snapshot が渡されても起動要求に出ないこと、実際の発話の保存が追加の Live 入力を起こさないこと、アプリの起動・購読経路が記憶の自動注入を持たないことをテストする。
既存の人格、発話、クイックチャット、音声の所有権と訂正・忘却の回帰テストも実行する。

必要時の参照には backing agent の応答待ちが加わる。実装で保証するのは過去の記憶の自動輸送を止める境界であり、モデルや音声認識の誤生成が絶対に発生しないことではない。必要な場面でモデルが参照指示に従う割合や待ち時間は、今回の静的・モック検証だけでは確認できない。
ライブ推論・マイク録音・設定変更・アプリ再起動を検証の前提にしない。
