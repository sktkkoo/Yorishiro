# 無音後の自発的な声かけ: Codex v3 の実装条件

Status: capability investigation complete; feature not implemented.
Issue: [#149](https://github.com/sktkkoo/Yorishiro/issues/149)
確認日: 2026-11-14。対象: インストール済み Codex CLI 0.169.0、Realtime v3、WebRTC。

## 確認結果

Issue が提案する `idle_timeout_ms` と `response.create` は、今回確認した
Codex app-server の実験的スキーマに、この用途の公開された操作として存在しない。
これは公開 Realtime API 全般の可否を意味しない。Yorishiro が実際に使用する
Codex v3 経路について、未確認のフィールドを送る根拠がないという結果である。

次のコマンドで、認証情報や会話を読まずにインストール済みバイナリのスキーマを
一時ディレクトリへ生成して再確認できる。

```sh
codex --version
codex app-server generate-json-schema --experimental --out /path/to/scratch/schema
```

| 確認対象 | 観測した契約 | この機能への意味 |
| --- | --- | --- |
| `ThreadRealtimeStartParams` | `model`、`initialItems`、`prompt`、transport 等。VAD idle timeout の設定項目なし | `idle_timeout_ms` を追加するだけの実装はできない |
| `ThreadRealtimeAppendTextParams` | 会話の文脈を追加する操作 | 応答生成や音声再生を確約するトリガーとして使わない |
| `ThreadRealtimeAppendSpeechParams` | `threadId` と `text`。説明は speakable text の追加 | 発話する内容を渡す経路であり、発話内容を生成する指示の経路とは区別する |
| app-server リクエスト一覧 | `thread/realtime/appendSpeech` は存在。`response.create` は確認できない | 別プロトコルの操作を推測で混ぜない |

[Codex 0.169.0 の実装](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/realtime_conversation.rs)
では `append_speech` が `StandaloneSpeech` をキューに入れ、v3 の送信側は
`RealtimeContextAppendChannel::Speakable` を設定して送信する。ここへ
「文脈に応じて質問してください」という制御指示を渡すと、その文自体が発話の
内容として扱われる恐れがある。RPC 受領も、実際の発話開始・完了の証拠ではない。

現状のアプリの `CodexRealtimeClient` には `appendSpeech` の呼び出しがない。
[自律作業の既存設計メモ](autonomous-document-work.md)にある発話連携の説明は、
現在のアプリでこの機能が実装・実機確認済みである証拠にはしない。
また通常の音声方針は無言を埋める反復質問を抑制しているため、単なるタイマー追加
だけでこの方針を無条件に反転させない。

## 実装する場合の経路

自発発話は既定で無効な opt-in 実験とし、次の二段階を区別する。

1. **発話候補の生成**: 最新の会話と作業状態から、短い発話内容、または「話さない」
   という結果を生成する。ユーザーが困っていると決めつけず、考え中・既に質問待ち・
   辞退済みの話題なら無言を選べること。発話候補の生成は仕事の新規実行や権限付与に
   しない。既存の Main Agent の実行中ターンを割り込ませたり、ユーザー発言を偽造
   して依頼キューに入れたりしない。安全に独立した候補生成経路を先に決める必要がある。
2. **候補の再確認と発話**: 同じ接続・会話世代であることと、まだ発話してよい状態かを
   再確認してから、実際に話す短文だけを native `appendSpeech` へ渡す。
   生成中にユーザーが話し始めた、ミュートした、無効化した、接続が変わった場合は破棄する。
   受領・発話開始・再生完了を別々に扱い、受領だけで成功と表示しない。

候補生成経路と native 発話の実機挙動が未確認の間は、動作しない設定スイッチや
未使用タイマーを製品に追加しない。将来 Codex が適切な idle trigger を公開した場合は、
そのバージョンの契約を再確認して最小の経路に切り替えられる。

## スケジューラーの条件

- 実験の初期候補は無音 60 秒、クールダウン 5 分。どちらも**未検証の設計値**であり、
  製品設定として実装済みではない。無音時間は調整可能、機能は常に無効化可能にする。
- 接続が active で、ユーザーが少なくとも一度発言したあとだけ候補を作る。
  ユーザー発言 1 回につき最大 1 回。クールダウン終了だけで再び発話しない。
- ユーザー音声、Realtime 応答、実際の出力再生、候補生成中は抑制する。
  マイクのユーザーミュートとデバイス中断、connecting/error、切断処理中も抑制する。
- 無音の起点は再生完了も考慮する。テキスト応答終了を音声再生終了と取り違えない。
- タイマー・生成結果には接続世代と会話世代を持たせる。発話・設定変更・停止・再接続で
  古い結果を無効にし、ウィンドウ復帰時に期限切れの声かけをまとめて送らない。
- 作業完了報告や明示的な通知と、この任意の声かけを同じキューとして重複実行しない。
  通常の割り込み・ターン制御を保ち、声かけのために音声接続を再作成しない。

## 残る検証と Issue の扱い

この変更は調査と設計条件の記録であり、#149 を完了扱いにしない。
実際の ChatGPT/API-key 認証で発話を開始する試験や、稼働中アプリの再起動は行っていない。

実装時は少なくとも次を検証する。

- 偽時計と遅延生成を使い、1 回だけの発話・クールダウン・無効化・ミュート・デバイス中断・
  発話開始・再生中・切断・再接続・バックグラウンド復帰の競合を確認する。
- 発話本文と制御指示を分離し、生成中の新しい会話によって古い候補が破棄されることを確認する。
- 実接続で、その時の会話に沿った低圧な短い発話を聞けることと、通常の割り込みが変わらない
  ことを確認する。RPC 成功や合成イベントだけでこの項目を通過にしない。
- 診断には状態遷移、世代、タイミングと抑制理由だけを残し、会話・音声・認証情報を複製しない。

完了に必要な未解決点は、独立した文脈付き発話候補の生成経路と、Codex v3 native 発話の
実機検証である。確認済みでない public Realtime API の機能を前提にした実装は行わない。
