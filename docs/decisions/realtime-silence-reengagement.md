# 無音後の自発的な声かけ: Codex v3 のローカル実験

Status: experimental implementation; live audio validation pending.
Issue: [#149](https://github.com/sktkkoo/Yorishiro/issues/149)
確認日: 2026-11-14。検証したプロトコル: Codex CLI **0.169.0**、Realtime v3、WebRTC。

## 通常利用への影響と有効化

通常利用では無効で、実験の設定項目も表示しない。共通のローカル開発者フラグ
`yorishiro:realtime-debug=1` と、この機能の端末別チェックボックスの**両方**が必要。
アップデートだけでは、追加の会話収集・推論要求・タイマー・計測を始めない。
設定はパックや共有設定に含めず、ローカルストレージだけに保存する。

開発者フラグを有効にした環境の設定画面で「実験: 無音後の声かけ」を選べる。
既定は無効、無音時間 60 秒（30–600 秒）、最短間隔 300 秒（60–3600 秒）。
これらは初期の実験値であり、有効性を実機で確認した推奨値ではない。
CLI の能力情報と、独立接続の initialize 応答がともに 0.169.0 を示す場合だけ動作する。
未検証の将来版・不明な版では停止する。対応版と利用料金の可能性は設定画面にも表示する。

## 発話経路

`idle_timeout_ms` や `response.create` を Codex app-server に推測で送らない。
生成された実験的スキーマには、この用途の公開操作として存在しない。
`thread/realtime/appendText` も発話生成のトリガーには使わない。

1. 有効化後、その音声接続で観測した完了済みのユーザー・アシスタントの発話だけを
   順番どおりメモリーに保持する。推測で発話のペアを作らない。最大 12 件、JSON で
   16,000 UTF-16 コード単位まで。単一発話が 4,000 単位を超えると途中で切らず、
   その回の声かけと履歴を破棄する。永続化・診断への複製はしない。
2. 無音と抑制条件を満たすと、同じ app-server に短命な別接続を作り、独立した
   ephemeral thread で `{speak, text}` の構造化候補を生成する。メインのモデル・
   プロバイダー・作業ディレクトリを読み、プロバイダーの暗黙フォールバックを禁止する。
   メインのターンを開始・中断せず、ユーザーの発話や新しい仕事として偽装しない。
3. 最大 240 Unicode 文字の発話本文か、`speak=false` と空文字列を受け取る。
   ユーザーが困っていると決めつけず、既に質問待ち・考え中・辞退済みの話題なら無言を
   選ぶよう指示する。候補の JSON は 8 KiB 以内、追加キーや不正な組み合わせは拒否する。
4. 接続世代と発話可能状態を再確認し、**実際に読む短文だけ**を native
   `thread/realtime/appendSpeech` に渡す。制御指示や JSON は渡さない。
   受領を実際の発話開始・再生完了として表示しない。

生成部分は[公式 temporary_structured_request](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/tui/src/temporary_structured_request.rs)
の隔離方式に基づく。環境・追加ツール・capability roots・workspace roots を明示的に
空にし、組み込みツール、拡張、skills、web search、そして `config/read` で得た
**全実効 MCP サーバー**を無効化する。設定取得失敗は続行しない。
元の実効 permission profile を確実に取得できないため、設定上の強い profile は流用せず、
read-only を要求・応答確認する。ephemeral、モデル、プロバイダーの不一致でも停止する。
予期しないツール項目や対話要求は拒否して中断する。この無効化一覧の証拠は 0.169.0 に限る。

[Codex の native 発話実装](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/core/src/realtime_conversation.rs)
では `append_speech` が `StandaloneSpeech` を送り、v3 は Speakable を使う。
ここへ「質問してください」というプロンプト自体を渡す構成は採らない。

## 抑制・キャンセル・資源上限

- 実際のユーザー発話 1 回につき候補生成は最大 1 回。失敗や「話さない」でも消費し、
  クールダウン終了だけでは再生成しない。
- ユーザー発話、Realtime 応答、出力再生、生成中は抑制する。ローカルミュート、
  マイク中断、音量ゼロ、非表示ウィンドウ、接続変更、停止、設定解除も対象。
- 新しい発話や状態変更で古い候補を破棄する。非表示時に履歴を消し、復帰だけでは
  期限切れの声かけを再生しない。通常会話や接続を声かけのために再起動しない。
- 候補生成は 30 秒で打ち切る。RPC は各 15 秒、接続待ちも 15 秒。
  start の RPC timeout 後は相関 ID をさらに最大 15 秒保持し、遅れた受領を回収する。
  後始末には別の有界 RPC 時間が必要で、生成期限と切断完了時刻は同じではない。
- 既知の専用 helper で開始処理中なら、[0.169.0 が明示的に対応する空 turnId の startup interrupt](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/app-server/src/turn_processor.rs#L1504)
  を使う。その後に届いた受領や所有 thread の通知から実 ID が分かれば、再度中断してから
  unsubscribe・独立接続の切断を行う。メインの thread に空 ID の操作は送らない。
- `unsubscribe` 自体は実行中のターンを止めない。ephemeral は `includeTurns` 付きの
  履歴再読も使えない。応答・通知・中断要求が通信障害で観測できない場合、プロバイダー側の
  実行停止や課金停止を保証できない。自動で生成を再送しない。
- 新しい helper 接続は 256 KiB を超えるフレームを JSON parse 前に拒否する。
  受領前通知は最大 32 件・合計 32 KiB、各 16 KiB、発話本文 8 KiB まで。

## 検証と残る受け入れ条件

偽時計・偽 transport による試験で、既定無効、版の制限、プロバイダー保持、ツール隔離、
1 回制限、クールダウン、候補の破棄、ミュート・解除・停止・再接続・復帰、通知順序、
遅延受領、timeout、開始中の中断、UTF-8 の上限を確認する。
テストは外部の推論・課金・実際のマイク・他のユーザーの会話を使わない。

実際の ChatGPT/API-key 接続で、会話に沿った低圧な短文が聞こえること、発話中の
自然な割り込み、連続利用時の頻度・遅延・料金は**未検証**。アプリ再起動やライブ推論は
行っていない。PR は実験コードを提供するが、これらの受け入れ条件が満たされるまで
#149 を完全解決として閉じない。
